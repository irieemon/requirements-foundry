  <action>
Add three new resources to the existing `RequirementsFoundryStack`, placed AFTER the IAM roles section and BEFORE the Stack Outputs section:

1. **CloudWatch Log Group** (CMP-04):
   ```typescript
   import * as logs from 'aws-cdk-lib/aws-logs';
   ```
   - `logGroupName: '/ecs/requirements-foundry-prod'`
   - `retention: logs.RetentionDays.TWO_WEEKS`
   - `removalPolicy: cdk.RemovalPolicy.DESTROY`

2. **FargateTaskDefinition** (CMP-01):
   - `family: 'requirements-foundry-prod'`
   - `cpu: 512` (0.5 vCPU)
   - `memoryLimitMiB: 1024` (1 GB RAM)
   - `executionRole: taskExecutionRole` (already defined above)
   - `taskRole: taskRole` (already defined above)

3. **Container** added to task definition:
   - `image: ecs.ContainerImage.fromEcrRepository(repository, 'latest')`
   - `logging: ecs.LogDrivers.awsLogs({ streamPrefix: 'app', logGroup })`
   - `environment` object with these keys:
     - `NODE_ENV: 'production'`
     - `PORT: '3000'`
     - `AWS_REGION: 'us-east-1'`
     - `S3_BUCKET_NAME: bucket.bucketName`
     - `RDS_SECRET_NAME: 'requirements-foundry-prod/rds-credentials'`
   - `portMappings: [{ containerPort: 3000, protocol: ecs.Protocol.TCP }]`

4. **FargateService**:
   - `serviceName: 'requirements-foundry-prod-service'`
   - `cluster` (already defined)
   - `taskDefinition` (from step 2)
   - `desiredCount: 1`
   - `securityGroups: [this.ecsSg]`
   - `vpcSubnets: { subnetType: ec2.SubnetType.PRIVATE_WITH_EGRESS }`
   - `assignPublicIp: false`
   - `circuitBreaker: { rollback: false }` (per research -- don't rollback during initial bootstrap when no image exists yet)

5. **Wire to ALB**: `service.attachToApplicationTargetGroup(targetGroup)`

6. **Add two new CfnOutputs** (append to existing outputs section):
   - `ServiceName` with value `service.serviceName`, export `rf-prod-service-name`
   - `LogGroupName` with value `logGroup.logGroupName`, export `rf-prod-log-group`

Do NOT modify any existing resources. The ALB listener already has a priority-1 rule forwarding to the target group -- no listener changes needed.
