| Status | Background | Text | Border | Rationale |
|--------|-----------|------|--------|-----------|
| open | bg-yellow-500/15 | text-yellow-700 | border-yellow-500/20 | Warning-adjacent: needs attention |
| in-progress | bg-blue-500/15 | text-blue-700 | border-blue-500/20 | Active work indicator |
| resolved | bg-green-500/15 | text-green-700 | border-green-500/20 | Success state |
| closed | bg-neutral-500/15 | text-neutral-500 | border-neutral-500/20 | Muted/archived state |

Source: RESEARCH.md code example for `STATUS_CONFIG`, adapted to use neutral instead of gray for consistency with shadcn neutral base.

## Layout Contract

### Page Structure (matches runs page pattern)

```
[PageHeader: "Bug Reports" + description]
[Content area: p-6, max-w-7xl mx-auto]
  [Card: border-border/50 shadow-sm]
    [CardHeader: title + description]
    [CardContent]
      [TableToolbar]
        [TableToolbarLeft: Status filter Select]
        [TableToolbarRight: report count text]
      [TableContainer]
        [Table]
          [TableHeader: Status | Submitter | Date | Page | Description]
          [TableBody]
            [TableRow: clickable, cursor-pointer]
            [TableRow: expanded content (colSpan=5), conditionally rendered]
```

### Expanded Row Layout

```
[TableCell colSpan=5, p-4 bg-muted/30 border-t border-border/30]
  [Grid: 2 columns on md+, 1 column on mobile, gap-4]
    [Left column]
      [Section: "Full Description"]
        [Text: body, whitespace-pre-wrap]
      [Section: "Browser Info"]
        [Text: label + body, muted-foreground for labels]
    [Right column]
      [Section: "Status"]
        [Select dropdown: current status selected]
      [Section: "Admin Notes"]
        [Textarea: 4 rows, placeholder text]
      [Save button: primary, right-aligned, full-width on mobile]
```

### Sidebar Integration

The Bug Reports nav item is inserted after the "Runs" item in the `navItems` array, conditionally rendered when `isAdmin` is true. The badge appears inline after the label text when the sidebar is expanded, and as part of the tooltip when collapsed.

## Interaction Contract

### Row Expansion (D-03)
- Click any table row to expand/collapse its detail panel below
- Only one row expanded at a time (clicking another row collapses the previous)
- Expanded row renders inline as a second TableRow with colSpan covering all columns
- Cursor: `cursor-pointer` on all table body rows
- Hover: `hover:bg-muted/50` on table body rows (standard table hover)

### Status Update + Notes Save (D-05, D-06)
- Select dropdown in expanded row shows all 4 statuses; any-to-any transitions allowed
- Textarea for admin notes, pre-populated with existing notes (or empty)
- Single "Save" button submits both status and notes in one server action call
- On success: `toast.success("Bug report updated")` + `router.refresh()` to revalidate data
- On error: `toast.error("Failed to update bug report")` with error message from server action
- Save button shows loading spinner and is disabled during submission (`saving` state)

### Dirty State Protection (Pitfall 4 from RESEARCH.md)
- Maintain a `Map<reportId, { status, notes }>` of pending edits at the table component level
- When expanding a different row, preserve unsaved edits in the map
- When re-expanding a row with pending edits, restore from the map instead of the server data
- No explicit "discard changes" prompt (internal tool, low risk)

### Filtering (D-07, ADMIN-04)
- Status filter: Select dropdown in TableToolbarLeft with options: "All statuses", "Open", "In Progress", "Resolved", "Closed"
- Default selection: "All statuses" (shows everything)
- Client-side filtering (dataset is small for internal corporate tool)
- Filter persists during the page session but does not use URL search params

### Sorting (D-07, ADMIN-04)
- Default sort: newest first (createdAt desc) from server query
- Date column header clickable to toggle asc/desc sort
- Client-side sort toggle (no server round-trip)
- Sort indicator: chevron-up or chevron-down icon next to "Date" column header

### Loading State
- Full table skeleton on initial page load: 5 skeleton rows matching column widths
- Save button shows spinner icon during submission

### Empty State
- Displayed when no bug reports match the current filter (or no reports exist at all)
- Centered within the table card area

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Keyboard navigation | Table rows focusable with Tab; Enter/Space to expand/collapse |
| Screen reader: expanded state | `aria-expanded` on clickable table rows |
| Screen reader: status badge | Badge text is descriptive ("Open", "In Progress", etc.) |
| Focus management | When row expands, focus moves to status Select in expanded row |
| Reduced motion | Shimmer and transition animations respect `prefers-reduced-motion` (global CSS rule exists) |
| Color contrast | All status badge text meets WCAG 2.1 AA (4.5:1 minimum) against their backgrounds |
| Touch targets | Select dropdown trigger and Save button minimum 44px height |
