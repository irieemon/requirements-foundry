**How to verify (9 steps):**

Step 1 -- Deploy the CDK stack (if not already done):
```bash
cd infra && npx cdk deploy --require-approval never
```

Step 2 -- Deploy the application:
```bash
./scripts/deploy.sh
```

Step 3 -- Wait for ECS service to stabilize (60-90 seconds):
```bash
aws ecs describe-services --cluster requirements-foundry-prod-cluster --services requirements-foundry-prod-service --region us-east-1 --query 'services[0].{status:status,running:runningCount,desired:desiredCount,deployments:deployments[0].rolloutState}' --no-cli-pager
```
Expected: running=1, desired=1, status=ACTIVE

Step 4 -- Get ALB URL:
```bash
aws cloudformation describe-stacks --stack-name RequirementsFoundryStack --query 'Stacks[0].Outputs[?ExportName==`rf-prod-alb-dns`].OutputValue' --output text --region us-east-1
```

Step 5 -- Verify application loads: Navigate to the ALB URL from the corporate network. The homepage should load with styled pages.

Step 6 -- Verify health check:
```bash
curl http://<ALB_URL>/api/health
```
Expected: 200 response with JSON health status

Step 7 -- Test file upload (STOR-02, STOR-03): Upload a test document through the UI. Verify it appears in the project. Confirm file exists in S3:
```bash
aws s3 ls s3://requirements-foundry-prod-uploads/ --region us-east-1
```

Step 8 -- Test AI generation (AI-01, AI-02, AI-04): Trigger card analysis or epic generation on an uploaded document. Verify it completes successfully (not returning mock/fake data). If Bedrock returns AccessDeniedException, the FTU form has not been approved yet -- wait and retry.

Step 9 -- Check container logs:
```bash
aws logs tail /ecs/requirements-foundry-prod --region us-east-1 --since 30m
```
