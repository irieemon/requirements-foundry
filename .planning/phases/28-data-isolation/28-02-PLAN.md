  <action>
    Read each file first, then apply these changes:

    **server/actions/projects.ts:**
    - Add imports: `import { getAuthorizedProject, getAuthorizedProjects } from "@/lib/auth/authorization";` and `import { getCurrentUser } from "@/lib/auth";`
    - `getProjects()`: Replace raw `db.project.findMany` with `getAuthorizedProjects()`. Return `projects` from the result. The include/_count should already be in getAuthorizedProjects (from Plan 01).
    - `getProject(id)`: Call `getAuthorizedProject(id)` first to verify ownership. Then use the returned project or re-query with the full include (the project detail page needs deep includes that getAuthorizedProject doesn't provide). Pattern: `await getAuthorizedProject(id);` then `return db.project.findUnique({ where: { id }, include: { ... } });` -- the ownership is already verified, the second query just gets the full data.
    - `getProjectName(id)`: Call `getAuthorizedProject(id)` first, then return `project.name`.
    - `createProject(data)`: Call `getCurrentUser()`, add `userId: user.email` to the create data. This is how DATA-01 is satisfied.
    - `updateProject(id, data)`: Call `getAuthorizedProject(id)` before the update.
    - `deleteProject(id)`: Call `getAuthorizedProject(id)` before the delete.

    **server/actions/analysis.ts:**
    - Add import: `import { getAuthorizedProject } from "@/lib/auth/authorization";`
    - For every exported function that accepts a projectId parameter: call `await getAuthorizedProject(projectId)` at the top of the function before any DB operation.
    - Functions like `getActiveRunForProject(projectId)` and `getRunProgress(runId)` -- for getRunProgress, if it takes a runId rather than projectId, look up the run's projectId first, then call getAuthorizedProject.

    **server/actions/generation.ts:**
    - Add import for getAuthorizedProject
    - Add ownership check at the start of each exported function that takes projectId

    **server/actions/batch-stories.ts:**
    - Add import for getAuthorizedProject
    - Add ownership check at the start of each exported function that takes projectId

    **server/actions/uploads.ts:**
    - Add import for getAuthorizedProject
    - Add ownership check for any function that takes projectId
    - For `createUploadFromText` or similar: verify projectId ownership before creating the upload

    **server/actions/epics.ts:**
    - Add import for getAuthorizedProject
    - Add ownership check for any function that takes projectId

    IMPORTANT: In server actions, if getAuthorizedProject calls notFound(), the Next.js framework handles it by rendering the 404 page. For functions that return structured responses like `{ success: false, error: string }`, wrap the getAuthorizedProject call in try/catch and return the error shape instead: `try { await getAuthorizedProject(projectId); } catch { return { success: false, error: "Project not found" }; }`. Check each function's return type to decide.

    IMPORTANT: Do NOT change the function signatures. Callers should not need to pass userId -- it comes from the session via getCurrentUser() inside the helpers.
