The script should:
1. Accept Neon connection string as first argument (or prompt for it)
2. Fetch RDS endpoint and credentials from AWS (CloudFormation outputs + Secrets Manager)
3. Run `pg_dump` from Neon with these flags:
   ```bash
   pg_dump "$NEON_URL" \
     --no-owner \
     --no-privileges \
     --clean \
     --if-exists \
     --format=custom \
     -f neon_full.dump
   ```
4. Run `pg_restore` into RDS:
   ```bash
   PGPASSWORD="$RDS_PASSWORD" pg_restore \
     --no-owner \
     --no-privileges \
     --clean \
     --if-exists \
     -h "$RDS_HOST" -p 5432 -U postgres -d requirements_foundry \
     neon_full.dump
   ```
5. Print verification queries to run afterward
6. Clean up dump file

Include clear comments explaining:
- Where to find Neon credentials (dashboard at console.neon.tech, local .env/.env.local, Vercel project settings)
- That the script uses `--clean --if-exists` to drop existing objects before restore
- That pg_restore warnings about "does not exist" on DROP are normal
- That the rename migration will apply on next container restart (entrypoint.js runs prisma migrate deploy)

The script should handle errors gracefully and print helpful messages if pg_dump or pg_restore fail. Include a `--dry-run` flag that shows what would happen without executing.

Make the script executable (chmod +x).

**Pre-flight: Locate Neon credentials**
Check these locations for your Neon connection string:

2. Neon Dashboard: https://console.neon.tech -> Your project -> Connection Details

**Run the migration:**
```bash

# Execute migration
./scripts/migrate-neon-to-rds.sh "postgresql://user:pass@neon-host/db?sslmode=require"
```

**If Neon credentials not found:**
Skip data migration. The RDS database already has the correct schema from Prisma migrations. You can start fresh with new data during the smoke test.

**After migration (or skip), restart the ECS container to apply rename migration:**
```bash
aws ecs update-service --cluster requirements-foundry-prod-cluster \
  --service requirements-foundry-prod-service \
  --force-new-deployment --region us-east-1 --no-cli-pager
```

**Verify schema after container restarts (~2-3 min):**
```bash
# Get RDS endpoint
RDS_HOST=$(aws cloudformation describe-stacks --stack-name RequirementsFoundryStack \
  --query 'Stacks[0].Outputs[?ExportName==`rf-prod-rds-endpoint`].OutputValue' --output text --region us-east-1)

# Get RDS password from Secrets Manager
RDS_SECRET=$(aws secretsmanager get-secret-value --secret-id requirements-foundry-prod/rds-credentials --region us-east-1 --query SecretString --output text)
RDS_PASS=$(echo $RDS_SECRET | python3 -c "import sys,json; print(json.load(sys.stdin)['password'])")

# Check columns exist (should show storageUrl, storageKey)
PGPASSWORD="$RDS_PASS" psql -h "$RDS_HOST" -U postgres -d requirements_foundry -c \
  "SELECT column_name FROM information_schema.columns WHERE table_name = 'Upload' AND column_name IN ('storageUrl', 'storageKey', 'blobUrl', 'blobPathname');"

# Check data counts (if migration was performed)
PGPASSWORD="$RDS_PASS" psql -h "$RDS_HOST" -U postgres -d requirements_foundry -c \
  "SELECT 'Project' as tbl, COUNT(*) FROM \"Project\" UNION ALL SELECT 'Card', COUNT(*) FROM \"Card\" UNION ALL SELECT 'Epic', COUNT(*) FROM \"Epic\" UNION ALL SELECT 'Story', COUNT(*) FROM \"Story\";"

# Check migration history
PGPASSWORD="$RDS_PASS" psql -h "$RDS_HOST" -U postgres -d requirements_foundry -c \
  "SELECT migration_name, finished_at, rolled_back_at FROM _prisma_migrations ORDER BY started_at;"
```
